## Energy review findings

- **Backlight dominates draw.** CPU already drops 240→80 MHz when the screen idles (`ui_main.cpp ui_poll_timer_callback`). Pedometer mode dims to 20.
- **LoRa was bleeding ~1.5 mA** in standby after boot and after every LoRa session → now slept (`3d1f35a`). ~1.5 mA continuous on a 470 mAh cell ≈ a meaningful chunk of a day.
- **NFC reader** (`loopNFCReader`) is gated by `_nfc_running`, only true while the (now-deactivated) NFC app is open → no idle cost.
- **WiFi** is brought up as `WIFI_STA` at boot (`factory.ino`) then disconnected; PHY may stay powered. Candidate: force `WIFI_OFF` until a connect is requested. Not yet changed.
- **Accelerometer** only enabled when IMU/Pedometer app opens — good.

### ESP32-S3 sleep modes (reference)
- **Modem-sleep**: CPU on, radio off between beacons. Pair with DFS.
- **Automatic light-sleep** via `esp_pm_config` (DFS: max/min MHz + `light_sleep_enable`): system auto light-sleeps when idle, wakes on demand; keeps WiFi via modem-sleep. Strong fit for a watch that mostly idles on the clock face.
- **Light-sleep**: clock-gates CPU/peripherals, RAM retained, ~hundreds of µA–mA depending on rails.
- **Deep-sleep**: CPU + most RAM + digital periph off, ~single-digit µA (measured 8.14 µA on WROOM-1). Already used for the alarm deep-sleep path.
- Docs: Espressif ESP-IDF "Sleep Modes" + "Current Consumption Measurement" (esp32s3).
